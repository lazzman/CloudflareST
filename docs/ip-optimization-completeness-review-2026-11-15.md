## 1. 结论

**尚未完整实现。核心业务链路已有代码和页面，但仍存在可复现的功能／契约缺口，不能标记“全部完成”。**

- 已实现但仍未实测：真实第三方联调、公网测速、完整 ICMP／IPv6 部署矩阵、最大候选规模。此类事项不等于没有代码，但不能列为验收通过。

## 3. 已确认缺口（按处理优先级）

以下 GAP 编号专用于本报告，不与设计契约 C-01／C-02 或上一轮 F-01～F-08 混用。未发现新的已实证 P1，本轮列为 P2／P3 的功能与完整性问题；这不代表全面安全审计。

### GAP-01／P2：DNS 读取／核对事实及投递详情未完整接通

- 后端目标发现返回当前值，但没有 `read_at` 字段；页面 `TargetFacts` 虽有“读取时刻”位置，真实接口永远无法填上该次读取时刻。定位：`internal/management/connections.go:231`、`internal/integrations/client.go:24`、`internal/management/web/src/components/TargetFacts.vue:12`。
- 超时后的只读核对只返回状态、原因和 Verified；没有将实际读取值／时刻作为结构化事实传递并保存。定位：`internal/integrations/alidns.go:290`、`internal/integrations/client.go:36`、`internal/management/types.go:91`。
- 普通投递行不展示本次写入 IP、开始／结束时间、核对标志；非保护目标没有相应详情展开。后端已有的部分数据也未呈现。定位：`internal/management/web/src/pages/RunDetailPage.vue:121`。
- 实测：模拟只读发现成功返回 `192.0.2.10`，`read_at=<nil>`；页面收到本次写入 IP 与处理时刻，却只显示目标名称、状态、ID 和理由。
- 依据：AC-77／78、CR-001 第 3.3 节、R3 目标复核与投递详情契约。补齐方向：记录真实观测值／时刻，区分快照、当前读取、最近确认写入及本次投递事实，并让页面可查。

### GAP-02／P2：无合格结果时，自动 DNS 没有明确的“未推送”结果

- `internal/management/runner.go:269` 仅在优选结论为 completed 时创建自动 DNS 投递。整次 no_results 时根本不生成跳过事实，即使启用自动 DNS 且已有明确目标。
- 页面对空投递回落为“未知／尚无投递”，而非已确认“无合格 IP，未推送”。定位：`internal/management/web/src/lib/domain.ts:88`。
- 实测：主状态 no_results、自动 DNS 开启、目标 1 条，最终投递列表为空；模拟外部调用为 0。
- 依据：AC-20。没有错误写 DNS，但状态要求不完整。补齐方向：为本次已配置目标留下未推送及原因，保持无网络写入。

### GAP-03／P2：保护命中后的自动跳过没有操作日志

- `internal/management/deliveries.go:134` 和取得目标锁后的保护分支保存 skipped 投递后直接返回，没有写入统一操作日志。
- 实测：目标保护有效，投递确实 skipped、外部调用 0；但独立操作日志数量仍为 0。
- 依据：CR-001 第 3.4 节明确要求重复命中保护及实际动作结果进入原脱敏日志；关联 AC-100、AC-110。不能用投递详情存在代替操作日志能力。
- 补齐方向：跳过事实与其脱敏日志一起持久化，不重试、不解除保护；覆盖两处保护守卫及幂等边界。

### GAP-04／P2：候选详情与历史快照展示不完整

- 候选行不读取 `candidate.sources`；来源区虽然能展开来源 JSON，但不能按 IP 查其全部命中来源。双来源候选的页面复验未见任一来源标记。
- `download_end` 已保存，却未展示“提前完整下载／窗口结束／失败”；显示字节数和时长不足以区分结束原因。
- 未执行下载的真实后端结构仍含默认 `download_bytes=0`、`download_seconds=0`，页面仅凭字节字段为 number 就渲染“0 字节 / 0 s”；独立页面复验确认此显示，尽管速度本身仍显示未测。应区分未测与实际零值。
- 配置快照只展示来源类型／值、URL、过滤顺序及门槛；抽样覆盖值、探测参数、正文／前置窗口、当次排序与非敏感通知／DNS 配置等未完整呈现。每步只有名称、状态及理由，没有完整逐步骤对照。
- 定位：`internal/management/web/src/pages/RunDetailPage.vue:109`、`internal/management/web/src/pages/RunDetailPage.vue:117`、`internal/management/web/src/pages/RunDetailPage.vue:118`。
- 依据：AC-09、AC-60／63、AC-83、AC-92／93 以及 PRD 第 3.8 节。补齐方向：以当次快照逐项展示，清楚区分未测、有效零值、失败以及下载结束方式，不改写测量结果。

### GAP-05／P2：队列位置、等待时长及实时进度不完整

- 队列只有入队／开始时刻，没有“第几位”、实际等待时长、当前运行已用时。列表用了 `ol`，但 `list-style:none` 隐藏默认序号；没有另行渲染位置。实测两条等待项均无显式位置／等待时长，当前席位无运行已用时。
- 进度对象仅保留当前阶段／单个 family／done／total；没有各族各阶段的持续计数集合，也没有失败／跳过的独立累计计数。文本“已处理不等于合格”不能替代这些信息。
- 定位：`internal/management/web/src/pages/QueuePage.vue:24`、`internal/management/web/src/pages/QueuePage.vue:25`、`internal/management/web/src/style.css:141`、`internal/optimizer/types.go:117`、`internal/management/runner.go:243`。
- 依据：AC-94～96、PRD 第 3.8 节及 R3 一致性进度快照。补齐方向：按真实队列显示 1 起始位置，使用服务端事实计算等待／运行耗时，按族保留阶段计数与失败／跳过／合格口径。

### GAP-06／P2：分页仅局部存在，轻量读取链路未落地

- 后端有 candidates 分页入口，但先反序列化整条运行再切片；运行列表、队列、进度响应仍携带完整 Run／Result。进度响应直接包含全部候选。
- 详情页面同时请求整次运行和进度，却不请求 candidates 分页 API，只在浏览器对完整数组切页。实测没有任何 candidates 请求。
- 持久层把整次运行及候选写成单一 JSON 对象，列表／调度／日志清理等使用按 kind 的全量读取；没有将候选分页与运行摘要／进度分离。
- 定位：`internal/management/http.go:163`、`internal/management/http.go:202`、`internal/management/http.go:205`、`internal/management/store.go:18`、`internal/management/store.go:41`、`internal/management/web/src/pages/RunDetailPage.vue:21`。
- 依据：技术 R3 第 7.2／11.1 节的轻量一致性进度、分页候选、分批保存与规模验证。不是“完全没有分页接口”，也未实测证明最大规模一定崩溃；但设计所要求的轻量链路确未完成。
- 补齐方向：拆分摘要、进度与候选读取／存储，接上服务端分页，避免两秒轮询重复传输整个候选集合，再做规模测试。

### GAP-07／P3：详情返回列表丢失筛选及页码

- 列表页码仅保存在组件 ref；进入详情没有保存列表上下文，详情返回链接也不携带筛选 query。
- 实测：指定手动触发筛选，在 21 条数据中翻到第 2 页，进入详情再点击页面“返回运行记录”，回到“所有触发＋第 1 页”。
- 定位：`internal/management/web/src/pages/RunListPage.vue:21`、`internal/management/web/src/pages/RunListPage.vue:28`、`internal/management/web/src/pages/RunDetailPage.vue:112`。
- 依据：UX R3 第 6 节明确要求返回列表恢复筛选和页码。补齐方向：保留安全的列表上下文；数据变化导致越页时明确提示并落到合法页。
