### 1.1 本轮建议结论

1. 以“优选任务”为默认首页，不先做装饰型统计大屏。
2. 五个一级入口：优选任务、运行队列、服务连接、操作日志、系统设置。历史和回收站始终在指定任务下，首期不新增跨任务历史混查页面。
3. 长配置使用独立编辑页，运行详情使用可直接打开的独立页面；弹窗仅承载短小选择与高风险复核，窄屏转为全屏面板。
4. 主状态、当前阶段、席位忙碌和投递状态分别表达，不能用一个“成功”概括整个执行。
5. 不新增批量删除、永久删除、导出、账号管理、DNS 记录创建或“测试 Webhook”入口。

## 2. 任务与信息架构

| 用户任务 | 起点与完成结果 | 主要风险与设计回应 |
| --- | --- | --- |
| 保存一套长期优选方案 | 新建任务 → 配置来源和规则 → 保存 → 任务概览 | 保存不等于运行或启用定时；分开显示四类开关 |
| 立即跑一次并检查结果 | 任务概览 → 立即运行 → 排队／运行详情 → 合格 IP | 队列和收尾可能很长；展示真实阶段计数，禁止虚构进度和 ETA |
| 定时维护优选与 DNS | 编辑计划及自动推送 → 概览核对时区、下一时点和目标 | 关定时不取消已有执行、不关闭 DNS 自动推送 |
| 从某次结果手动更新 DNS | 指定任务历史 → 执行详情 → 选目标及匹配 IP → 复核 → 投递明细 | 旧历史可能覆盖新 IP；展示记录身份与覆盖风险，未知结果不能直接当失败重发 |
| 排查为什么无结果或推送异常 | 任务记录筛选 → 阶段／候选判定／投递详情 | 区分系统故障、无合格结果、未测、未启用与真实 0 |
| 管理共享配置及历史 | 连接／任务归档／回收站／操作日志 | 不回读秘密；活动引用保护；删除历史不撤销外部操作 |

### 2.1 导航树

- 登录（未认证入口）
- 优选任务（默认首页）
  - 活跃任务／已归档任务视图
  - 新建或编辑任务
  - 任务概览
    - 该任务运行记录
    - 单次运行详情
    - 该任务回收站
- 运行队列（全局当前执行及等待队列，不是跨任务历史列表）
- 服务连接（阿里云、Telegram、企业微信）
- 操作日志（共享只读）
- 系统设置（时区、历史保留、认证说明与环境能力）

页面顶栏持续显示全局当前执行入口、队列数量及系统时区；任务页和记录页保留任务名与稳定 ID。任务改名不改变记录归属。桌面全局管理菜单及窄屏菜单均提供有文字标签的“退出登录”，不增加第六个业务导航入口；退出只结束当前会话，不停止后台执行或退出其他使用者。

### 2.2 页面与路由候选

以下路由是设计建议，不代表已存在的接口或页面。浏览器返回应恢复相应任务及已应用的非敏感筛选。

| ID | 页面／候选路由 | 主信息与主动作 |
| --- | --- | --- |
| P01 | 登录 `/login` | 单一密码字段、登录、冷却提示；不展示任务数据或账号注册 |
| P02 | 任务列表 `/tasks` | 名称／ID、地址族、计划与推送开关、活动执行；活跃视图可新建／运行，已归档视图提供“恢复任务”及历史入口，不接受新运行 |
| P03 | 任务编辑 `/tasks/new`、`/tasks/:taskId/edit` | 分组配置、校验与保存；明确只影响新执行 |
| P04 | 任务概览 `/tasks/:taskId` | 已保存配置摘要、当前执行、下次时点；活跃任务运行／编辑／定时启停／归档；归档任务显示“恢复任务”，不提供新运行入口 |
| P05 | 队列 `/queue` | 当前执行与阶段、FIFO 位置、等待时长；打开详情、取消排队或停止当前执行 |
| P06 | 任务记录 `/tasks/:taskId/runs` | 入队时间、主状态、触发方式、DNS／通知状态筛选及已确认摘要 |
| P07 | 执行详情 `/tasks/:taskId/runs/:runId` | 概览与进度、全部合格 IP、全部候选、来源及预算、当次快照、投递明细；可用记录有“发送本次摘要”，已有投递另有单渠道重发 |
| P08 | 回收站 `/tasks/:taskId/recycle-bin` | 删除时间、剩余可恢复期、原执行时间；恢复，不提供直接永久删除 |
| P09 | 连接 `/connections` | 类型、名称、凭据已设置状态、引用与忙碌原因；新建、替换凭据、解绑后删除 |
| P10 | 操作日志 `/operations` | 时间／动作／对象／结果筛选、主体类别与脱敏原因；无改删入口 |
| P11 | 系统设置 `/settings` | 时区、历史保留、密码来源及会话说明、ICMP 能力；不提供网页密码找回 |
| P12 | 异常状态页 | 会话失效、资源不存在、读取失败；安全返回，不引入虚构的个人权限角色 |

## 3. 关键页面文字线框

以下仅说明信息顺序和动作位置，不是已实现截图。中括号为控件，状态均为说明性占位。

### 3.1 P04 任务概览：先识别配置，再执行

~~~text
任务名称 · 稳定 ID
[立即运行] [编辑配置] [更多]
定时：关闭／开启 · 时区
下次运行：实际未来时点或未启用
DNS 自动推送：关闭／开启
通知：Telegram／企业微信各自开关
当前执行：主状态 · 阶段 · 席位
[查看进度] [查看运行记录]
来源与地址族摘要
过滤顺序／门槛 · 结果排序
选中 DNS 目标与共享连接引用
~~~

“立即运行”仅发起本次运行。点击后得到执行 ID 再进入详情；按钮转“查看当前执行”，不把浏览器跳转成功当作已入队证明。

### 3.2 P03 任务编辑：分组长表单

~~~text
编辑任务 · 当前配置版本
保存只影响后续新执行
[基本信息与来源]
[测速、过滤及结果排序]
[抽样与扩采预算]
[定时计划]
[DNS 与通知]
页面级错误摘要（失败时出现）
[取消编辑] [保存配置]
~~~

桌面可用页内锚点导航；窄屏纵向展开。分组不是独立业务草稿，只有整页通过校验并保存后才形成新任务配置。保存失败保留合法输入；不会保存一半或启用计划。

### 3.3 P07 执行详情：主结果与后处理分开

~~~text
任务 / 执行 ID · 触发方式
主状态：运行中
当前阶段：DNS／通知自动收尾
席位：仍占用 · 运行已用时
优选阶段结果：已产生／尚未产生
[进度] [合格 IP] [全部候选]
[来源与预算] [当次快照] [投递]
每地址族：已处理／已知总量
DNS：逐目标实际状态
通知：逐渠道实际状态
[停止执行] 或结束后的合法动作
~~~

即使已有最终合格 IP，正常收尾期间也不把主状态提前标成已完成。结果可查看，下一轮仍不可触发；这不是增加一种“收尾中”主状态。

## 4. 核心流程及操作契约

### 4.1 新建任务 → 保存 → 运行 → 查看

1. P02 新建 → P03，带入 PRD 默认值：只开 IPv4，ICMP Ping，三项过滤开启，定时／DNS 自动推送／两种通知均关闭。
2. 来源支持组合；“全部 IP 段”说明为项目清单，不是互联网全量扫描；域名在实际开始时解析，编辑时不伪造最终候选总量。
3. 保存校验成功进入 P04；显示仍然关闭的计划和推送开关，禁止保存顺便执行或发测试通知。
4. 立即运行得到入队收据后进入 P07；忙碌时链接既有执行，不新建重复实例；其他任务按 FIFO 等待。
5. 来源、初采、扩采、过滤、下载、排序及自动收尾按实际阶段更新。总量未知显示待确定，失败／跳过不冒充合格。
6. 收尾结束后显示最终主状态和逐目标／渠道投递结果；配置编辑仅影响新执行，当次快照不变。

### 4.2 手动 DNS 推送：显式选择与复核

- 入口：P07 的合格结果；已删除不可用的记录不作为可操作数据源。先保留来源执行 ID、原执行时间和当次结果身份。
- 选择：从已授权可用连接的现有域名／A 或 AAAA 记录中明确选目标；每条目标只选一个匹配地址族的合格 IP，不提供自由填写任意新 IP 的捷径。
- 复核：展示账号非敏感名称、记录身份／类型、当前读取到的 IP 及读取时刻、候选 IP、来源执行时间，以及目标在本系统内最近已知且已确认的写入任务／执行／时间。来源执行时间与目标写入时间分开显示；旧历史提示可能覆盖较新结果，说明仅换 IP、TTL／线路不变、其他记录不动。
- 最近写入来源或时间未知时明确标为未知，不用当前时刻或本次来源执行补齐；该元数据来自本系统已确认的写入事实，不代表监控了系统外全部改动，也不因读取到相同 IP 就推断写入人。
- 提交：网页在发起动作前生成并保留稳定操作号；收到响应后再关联实际投递 ID。首次响应丢失时仍可显示原操作号并只读查询，不假设已取得投递 ID，不换号盲重发；关闭面板不等于取消已提交动作。
- 明确失败：保留成功目标，仅允许按失败目标重试。结果未确认：展示系统核对结果及重复风险，由用户明确决定人工重试，不自动写入或回滚。
- DNS 核对后仍未确认的目标展示“自动写入暂停，待人工处理”、原投递及形成时间；人工重试必须明确确认重复及迟到覆盖风险，重试本身不解除暂停，其他目标不受影响。解除为第 4.5 节的独立动作，不与提交／成功提示合并。
- 未找到匹配地址族的自动结果时不改 DNS；配置 AAAA 不自动打开 IPv6，可解释本轮该目标可能跳过，而不是暗中改变任务。

### 4.3 停止、删除、归档和恢复

| 操作 | 操作前复核 | 反馈及恢复 |
| --- | --- | --- |
| 取消排队 | 执行 ID 和任务；该执行尚未取得席位 | 显示取消结果及允许的取消摘要，不抢占正在运行的其他任务 |
| 停止运行 | 明确当前阶段，尤其可能已有外部写入 | 先显示停止请求已受理；收到真正停止及收尾结论后更新。已有外部成功不撤销 |
| 删除执行记录 | 必须已结束且不受活动执行保护；二次确认具体记录 | 进入 7 天回收站，不撤回 DNS／消息；活动执行按钮禁用并说明原因 |
| 恢复记录 | 显示原运行时间和剩余恢复期 | 恢复后重新起算运行历史保留期，不重跑、重推送或改原执行时间 |
| 归档任务 | 任务无排队／运行／自动收尾引用 | 归档不删历史、不再接受新触发；恢复后定时关闭，DNS 自动推送配置不随意改变 |
| 恢复任务 | P02 已归档视图或 P04 归档概览的“恢复任务”，明确目标任务 ID，区别于恢复运行记录 | 成功进入活跃任务概览，定时保持关闭，来源、规则及 DNS 自动推送配置保留；不运行、不入队、不发 DNS 或通知。失败保留原归档状态并说明原因 |
| 删除连接 | 先解除任务引用且无活动引用 | 阻断时列引用对象入口，不提供强制删除或自动改绑其他目标 |

### 4.4 首次手动发送摘要与重发

- 对指定可用运行记录，在 P07 提供“发送本次摘要”，包括从未投递过、自动通知保持关闭的情形；不得以没有失败投递或自动开关关闭为由隐藏首次手动发送能力。
- 面板明确本次渠道及可用连接引用，每种渠道选一个连接；没有可用连接时给配置入口，不复活失效的历史引用，也不自动改绑或开启任务自动通知。记录可用性由服务端按基线核验，本文不新增主状态资格限制。
- 复核显示任务、执行 ID／原时间、已知结束结论、合格数量及真实指标；确认后只发送本次明确选择的摘要，不重跑优选或 DNS，不改变自动通知配置。
- 首次发送不要求原投递 ID；对已有投递的重发则显示原渠道、结果及原尝试身份，失败或未确认渠道可独立处理。未确认重发提示可能重复，已成功渠道不随“重发失败项”再次发送。
- 网页在提交前保留本次操作号，受理后再显示关联投递身份及逐渠道结果，受理不等于已送达。首次响应丢失时按 C-01 已确认协议只读查原操作号，不能靠新建动作绕过结果未知。

### 4.5 DNS 目标自动暂停与人工解除（C-02 已确认 A）

- P07 投递详情及 DNS 目标复核面板展示目标级保护，P09 的 DNS 目标信息可查看同一状态；按实际账号及记录身份识别，不按某个任务或连接显示名分别计算。共享目标的所有任务均受该保护，通知渠道不受影响。
- 后续自动推送命中保护时显示“未推送／跳过：目标待人工处理”，附原未确认身份；不发送写请求、不等待人工解除。本轮优选及其他目标／通知照常处理，全部收尾有结论后正常定稿并释放席位，不自动关闭任务定时或自动推送开关。
- 提供“查看原未确认操作”“核对目标记录”和“解除自动写入暂停”入口；只读核对不写 DNS、不自动解锁，人工推送／重试仍走明确目标与重复风险复核。
- 解除面板展示具体账号／记录、原未确认操作、当前可读取的值及读取时刻（不可读取则如实说明），以及“旧远端请求仍可能迟到，解除不代表旧请求已停止”。共享认证使用者处理并明确确认后，才发起独立解除动作，操作号遵守 C-01。
- 解除成功只恢复该目标后续自动写入资格，不更新 IP、不立即执行新优选、不重试或补发已跳过操作，不修改任务开关，也不改写原未确认记录；失败／冲突保留暂停并刷新原因。自动推送暂停与解除状态不能仅保存在浏览器，刷新、重启或历史清理不会自动解除。
- 若解除前保护版本已有新未确认原因，提示重新查看最新事实并复核，不默认清掉新保护；动作结果进入既定脱敏操作日志，不增加实名审批或新的个人权限。

## 5. 表单与内容规则

| 配置组 | 必须表达的事实 | 防错及恢复 |
| --- | --- | --- |
| 来源及预算 | 每 CIDR 默认 256；每族上限默认 10000，均只接受 1～100000 整数；定向超限整次失败 | 不展示“0 为无限制”；说明 /24 或 /120 扩采可能超出逐个手填范围，但遵守原来源边界 |
| 延迟与失败比例 | ICMP／TCPING；成功探测中位数；默认 5 次、每次 1000 ms；TCPING 默认 443 | ICMP 不可用提示改选路径，不能自动切换；TCPING 用“连接探测失败比例”，不宣称链路丢包 |
| 过滤与排序 | 默认 ≤200 ms、≤20%、≥5 MB/s；1 MB 为 1000000 字节 | 延迟／丢包可调序，下载固定后置；提供上下移按钮，不要求只能拖拽 |
| 下载 | 测速文件 URL，默认沿用项目 DefaultDownloadURL，可按任务覆盖为 HTTP／HTTPS 地址；每启用族默认最多 20 个；正文窗口默认 10 秒、范围 1～60 秒；前置合计等待独立默认 10 秒、范围 1～60 整数秒 | URL 格式错误定位字段并阻止保存，不静默换址；默认地址可用性未实测，执行失效明确报告；下载关闭后速度未测，“下载关闭＋速度优先”阻止保存；不另设正文停滞超时 |
| 计划 | 快捷周期或五字段 Cron，最短 1 分钟，统一系统时区及下一未来时点 | 保存计划不自动启用；关闭只停未来触发，已有执行不变；无效输入保留原有效计划 |
| DNS | 共享连接、明确的现有记录、自动推送开关 | 默认关闭；不提供新建记录或改 TTL／线路字段；目标已变时不静默换目标 |
| 通知 | Telegram／企业微信各引用一个连接，可同时开 | 默认关闭，独立于 DNS；保存不发测试消息；P07 可首次手动发摘要，已有投递另可重发失败／未确认渠道，二者不依赖开启自动通知 |

任务有活动执行时允许编辑仅影响未来的非敏感任务配置；当前引用连接的凭据或目标变更、任务归档仍受保护。不能为简化表单一概禁掉所有任务编辑，也不能让编辑回写旧快照。

下载 URL 与其他任务配置一起保存，固定在当次非敏感快照中，后续修改不影响旧执行。说明默认值来源，不以格式通过宣称文件可用；“恢复默认”若提供，仅改变未保存表单，仍须保存才生效，不发起下载测试。秘密材料不因 URL 输入而进入普通日志或明文历史，具体脱敏由技术稿承接。
