### 1.1 推荐架构

推荐“模块化单体”：Go 管理服务＋内置前端静态资源＋SQLite 本地持久化＋进程内单消费者调度／执行器，直接对接阿里云 DNS、Telegram 与企业微信。

前端候选为 Vue 3＋TypeScript＋Vite＋管理组件库（优先评估 Element Plus）；后端优先使用 Go 标准 HTTP 能力，业务模块独立于路由层。构建时生成静态资源并嵌入管理端产物，运行时同源提供页面与 API，不要求独立 Node 服务。

该选择利用已有 Go 网络能力和单实例串行需求，避免首期引入 Redis、消息中间件、微服务或独立数据库服务。组件库、驱动及 Go 版本不在本稿锁定未经验证的具体依赖版本；见第 12 节取舍。

## 3. 系统边界与部署形态

### 3.1 分层关系

~~~text
浏览器：管理页面与记录查看
            ↓ 同源 HTTPS／会话
Go HTTP 入口：认证、校验、查询
            ↓ 应用服务
任务／计划／执行／投递／日志
            ↓
持久化队列 → 单消费者运行协调器
            ↓
来源 → 测量 → 筛选排序 → 自动收尾
~~~

侧向依赖：

- SQLite：配置、队列、快照、结果、投递、会话及日志元数据；网络 I/O 不占用长数据库事务。
- 本地受保护卷／秘密材料：SQLite 数据及 WAL、加密凭据所需材料、备份及迁移元数据。
- 外部网络：运行时来源域名解析、候选 IP 的 ICMP／TCP／下载，以及三类服务连接；对外写入只能经过投递协调模块。
- 可选反向代理：TLS、访问入口和可信代理来源配置；不是产品必需的第二个应用服务。

### 3.2 单实例约束

同一个数据卷只允许一个管理实例拥有调度／执行权。启动时取得独占卷锁，失败即拒绝以活动实例启动；不能只靠前端隐藏“运行”按钮或进程内互斥锁防止两个容器各跑一个任务。首期不支持多副本部署、共享 NFS SQLite 或自动主备切换。

HTTP 请求可并发，低层延迟探测可有界并发，但“一个运行席位”不是“整个服务器只有一个 goroutine”。下载在该运行内逐个 IP 进行，不与下一任务重叠；DNS 手动操作仍按同目标串行，不因不占优选席位而绕过目标锁。

## 4. 模块职责与所有权

| 模块 | 核心职责及读写责任 | 禁止承担的行为 |
| --- | --- | --- |
| Web／认证 | 请求入口、共享会话、来源限流、CSRF／Origin 校验、字段校验与错误映射 | 不在处理器直接修改运行状态或调用服务商写入 |
| 任务与连接 | 任务版本、计划／来源配置、连接引用及凭据替换，执行期保护 | 不修改已入队快照，不回读秘密，不自动替换目标身份 |
| 计划器 | 五字段 Cron、快捷周期、统一时区、下一未来时点与触发事件 | 不补停机漏跑，不把关闭计划当成取消队列 |
| 入队协调 | 原子校验任务活动性、生成执行 ID／FIFO 序号、固定快照 | 不允许同任务两个活动执行；手动请求不抢占 |
| 运行协调器 | 单席位、阶段推进、取消传播、核心结果与正常收尾、最终状态提交 | 不按整项时长终止，不在测速结束就释放 |
| 来源与采样 | 地址族、解析、去重来源标记、预算与单轮扩采计划 | 不全量展开巨大 IPv6 网段，不重复计数或返还淘汰预算 |
| 测量与判定 | ICMP／TCP 探测、正文测速、原始精度汇总、逐步骤判定与排名 | 不输出含糊的 0 速度，不静默切换协议，不继承旧 CLI 早停语义 |
| 投递协调与适配器 | 明确目标、单目标锁、DNS 读写与核对、目标自动保护资格、独立人工解除及逐渠道通知／重试收据 | 不承诺外部恰好一次，不自动解除保护或重试，不在重启后重放 |
| 查询与进度 | 任务内记录、候选分页、快照、分阶段一致性视图 | 不把预算上限当实际总量，不生成总体百分比或 ETA |
| 生命周期与操作日志 | 历史／回收站／归档联动、日志 30 天清理、关联保护 | 不改写外部 DNS／消息，不递归记录普通浏览或日志清理的无限日志 |

应用服务是业务状态写入的唯一入口；仓储层提供事务和版本比较，不让多个模块各自绕开协调器改同一执行。

## 5. 一次运行的数据与控制流

### 5.1 入队与计划一致性

1. 手动触发携带客户端在提交前生成的稳定 operation_id；服务端核验格式、重复身份及请求摘要，在事务内检查未归档、任务不存在活动引用，固定非敏感快照及连接／目标引用，分配单调 FIFO 序号。操作身份与实际执行 ID 分开。
2. 写入排队实例及操作收据后返回执行 ID；提交失败不返回“已排队”。同动作标识重复请求返回原收据，同任务另一个新动作在忙碌时返回既有执行身份。
3. 定时触发使用同一入队入口；忙碌只写跳过事件，不创建新实例。手动和定时共享 FIFO，没有优先级。
4. 计划保存、启用或时区变更在事务内更新计划版本及严格晚于生效时刻的下一时点；调度器处理前重新比较版本，丢弃旧计划尚未发生的未来触发。
5. 关闭计划只停止后续触发，已有队列、运行及 DNS 自动开关保持不变。队列由数据库保存，不能只存在内存 channel。

### 5.2 执行流水线

- 取 FIFO 首项并原子取得席位，主状态排队中 → 运行中；创建该运行独立配置、上下文、计数器和低层资源，不读可变化的任务对象作为运行配置。
- 实际开始时解析来源；按族去重定向 IP。任何启用族 D>B 则形成优选失败结论，不截断定向 IP、不测速或更新 DNS；部分来源失败仅留警告，本轮全无候选失败。
- 剩余 R=B-D；初采名额为 R=0 时 0，否则 min(R,max(1,floor(0.8×R)))。按 CIDR 均衡且受容量约束分配，实际新增去重初采 S 后扩采额度 E=B-D-S；相同 IP 从一开始只占一个累计名额，重复来源不新增占额。已经纳入预算的候选在测试失败或过滤淘汰后不返还名额，这与重复地址不额外计数不同。
- 初始批次完成后，对各族全部成功测得有效初始延迟的 IP 按原始延迟取前 ceil(0.1×N)，并列按 IP 数值；不能擅自把“前置过滤已通过者”代替这一触发集合。
- 按 /24 或 /120、原来源边界及最佳触发延迟优先追加未测地址，只扩一轮。初始／扩采结果合并完成前置筛选后，按延迟和 IP 数值统一预选每族下载候选，默认每族最多 20。
- 下载逐 IP 完成，形成各步骤结论及最终分族排序；最终合格结果保存到 core_result，主状态仍运行中。
- 自动 DNS 按本轮匹配地址族最终第一名处理；写前读取实际目标保护，存在自动暂停则仅记录跳过原因并继续其他目标，不等待人工解除。之后处理已启用结束摘要，内容取 core_result 与已知 DNS 结果，不要求主状态先为已完成。
- 全部本轮自动处理得到成功、失败、未确认或跳过等结论后，事务内写正常终态、收尾结束时间并释放席位；再允许下一执行开始。投递失败不覆盖优选成功。

### 5.3 取消及重启

- 停止动作先记录 cancel_requested，协调器阻止新的 DNS 或业务消息调用、取消本地探测／下载并等待所有在途本地资源退出；不能把发出取消信号当作真正停止。
- 已提交的外部请求可能仍生效，保存实际或未确认结果，不声称回滚；已启用渠道允许一次取消摘要例外，按基线处理，不自动重试。
- 对已持席位的执行，停止确认及允许的取消收尾处理结束后才释放；主状态为已取消，已有测量结果保留。已在正常收尾时停止也不把它改回普通已完成。
- 排队取消不为摘要抢占其他运行的席位；该执行尚在处理通知时仍保护其连接／活动引用，不能仅凭主状态已取消就撤销保护。正常摘要已发送的外部事实不撤回，相同结束事件不重复发送。
- 进程重启先取得独占卷锁，在开放新触发前将旧活动运行标为已中断、旧队列标为已取消并保留原因；结束旧运行权，释放活动引用，不恢复旧队列、运行或待投递动作，不补发旧摘要。
- 在途投递没有持久化确认时标记未确认；不能因为重启就记录为未写入／未送达。新请求或下一未来计划才产生新执行。

## 6. 测量引擎的必要契约

### 6.1 配置与数值

- ProbeConfig／SamplingConfig／FilterConfig／DeliveryPlan 为运行级值对象候选；包级全局 flag 不作为服务端配置来源。
- 每 IP 的成功探测耗时在内存中汇总，取中位数；偶数取中间两值平均，失败次数／实际次数独立计算。持久化成功数、失败数、实际次数、中位耗时及原因，不要求原始探测报文。
- 使用未舍入精度过滤、排序及扩采；延迟采用明确的时长精度，下载速度保存字节数和有效时长后派生，避免把显示小数再写回判定。
- 单位统一十进制 MB/s。延迟优先：延迟升序、速度降序；速度优先：速度降序、延迟升序；最后为标准化 IP 数值。关闭下载时无速度键，且不能保存速度优先。
- 候选键为运行＋地址族＋规范化完整 IP，来源使用关联集合；仅对允许范围生成至多预算内地址，不通过整网段展开后截断实现数量限制。
- D、S、X 只累计本轮新增的去重候选；发现重复 IP 只追加来源关联，不再次增加候选或扣减预算。例：同一 IP 命中 3 个来源只占 1 个名额；该 IP 测试失败后仍占这 1 个名额。初采未实际新增的名额仍可按既定公式转入扩采，不用重复地址凑数。

### 6.2 下载与目标连接

- 连接地址固定为候选 IP，HTTP Host、HTTPS SNI 与证书校验依据配置 URL；不能让普通域名解析悄悄把连接目标换成其他 IP。默认不继承不受控环境代理，否则需能证明实际测量目标仍正确。
- 下载 URL 的端口、候选连接端口与 TCPING 端口应分别建模：TCPING 按任务端口，HTTP／HTTPS 文件请求按 URL 端口或其协议默认端口；不将旧 CLI 的共享端口变量直接带入。此实现解释需在评审中明确，避免隐藏耦合。
- 前置等待合计默认 10 秒，可按任务 1～60 整数秒，从开始建连至拿到响应头；该计时涵盖 TLS 及允许的重定向链，不能每跳重新得到完整预算。
- 开始读取正文时才启动独立正文窗口，默认 10 秒，范围 1～60 秒；全程单调经过时间包含停滞。网络读取必须有受窗口截止时间控制的取消路径，不能仅在下一次 Read 返回后才检查到期。
- 文件提前正常完整结束，按实际字节和时长计算；窗口到期已有有效数据且无真实错误也形成样本，结束原因为窗口完成而非文件完整；零字节、无正时长或真实连接／读取错误为失败，已读部分数据不挽救真实错误。
- 不另设连续无数据超时，不重复下载凑时长；不得用覆盖建连＋正文的单一 HTTP Client.Timeout 取代两个窗口。
- 重定向候选：限制为同源且保持候选 IP，限制跳数，拒绝降级和不受控跨源跳转；这是安全实现提案，需验证默认 URL 和自定义 URL 的实际兼容性，不能静默换 URL 或关闭证书校验。若必须放宽并改变测量对象，先评审，见 T-06。

## 7. 持久化模型、事务与查询

| active_refs／execution_slot | 同任务活动引用唯一、全局槽唯一；队列／运行／取消收尾引用受保护；卷锁保证单实例 |
| run_sources／sampling_facts | 本轮解析、来源成功失败、分族预算、初采分配、扩采触发／范围／新增及不足原因 |
| candidates／candidate_sources／filter_decisions | 规范 IP、汇总指标、下载字节／时长／结束原因、来源集合、逐步骤结论及最终合格名次 |
| delivery_attempts／target_write_facts | 动作／事件标识、明确目标、期望 IP、处理状态、外部结果、核对结果和最近已确认写入来源；每次人工重试为新尝试 |
| dns_target_write_guards | 服务商＋稳定账号身份＋记录 ID 的目标级自动写入保护、原因、原未确认身份、形成时间及保护版本；独立于运行主状态／任务配置／连接别名，不随历史或日志清理删除有效保护 |
| operation_receipts | 客户端稳定 operation_id、动作及请求摘要、受理结果、关联运行／投递等对象 ID；跨重新认证可查，非登录凭证；保存及过期识别须覆盖结果未知场景，不能把旧号无记录当作允许重新执行 |
| sessions／auth_limits | 不透明会话 token 的摘要、7 天截止与密码世代；来源失败计数及冷却状态 |
| operation_logs／record_tombstones | 轻量日志及简要删除事实，事件时间起固定 30 天；不记录秘密或普通查询，不设逐条改删 API |
| settings／schema_migrations | 统一时区、历史保留、存储版本、备份所需元数据；不把随机启动密码当作持久登录权 |

### 7.1 原子边界

1. 入队：检查任务与活动引用＋快照＋FIFO＋动作收据及轻量操作日志同一事务；计划触发版本也须核对。
2. 取得席位：队列项到运行、实际开始时间和槽占用同一事务；配置／连接保护在此之前已覆盖排队期。
3. 阶段写入：小批量结果、计数及 progress_revision 一起提交；不可先宣称已处理而结果尚未可读。网络探测不持有写事务。
4. 终态：正常定稿＋结束时间＋释放活动引用及席位同一事务；停止请求与终态提交竞争时使用版本比较，使先后结果有唯一解释。
5. 外部投递：先持久化明确目标的尝试，再在数据库事务外调用，回来持久化结果；数据库与第三方之间没有分布式事务，崩溃时可能只能得到未确认。
6. 任务归档、连接变更、记录删除／恢复再次核验活动引用和版本，不能信任浏览器之前的按钮状态。手动投递与删除等竞争需在对象版本／引用层串行核验，具体锁顺序列为实施前细化项，不能丢掉已提交的投递收据。
7. DNS 未确认结论与对应目标保护在同一短事务落库后，才放开该目标的本地写入序列；事务不覆盖网络调用。若不能持久化保护，不得在当前进程中把该目标当作可自动写入，数据库故障沿既定禁止新增副作用路径处理。解除持有相同目标互斥并比较保护版本，版本变更返回冲突，不清除用户未处理的新原因。

### 7.2 查询与保留

- 记录以 task_id 限定查询；即使共享管理身份，也验证 URL 中任务和执行的实际归属，避免把错误对象当正确目标。
- 记录排序建议入队时间倒序＋ID 稳定次序；时间筛选按入队时间。投递条件用独立 EXISTS：DNS 任一目标命中、通知任一渠道命中；不同筛选条件同时满足。
- 进度快照一次返回当前阶段、主状态、席位、分族分阶段 done／known_total、单位、更新时间和 revision；unknown total 用空值及原因，不用 0。计数与结果来自同一已提交视图。
- 活动记录不进入保留清理。运行历史默认结束后 30 天、再入 7 天回收站；恢复重算保留锚点但不改原执行时间，不重跑或重推送。
- 操作／简要删除日志按事件固定 30 天清理，不进回收站，恢复不刷新时间；删除历史后日志可显示对象已删除和稳定 ID，不要求不存在的对象还能打开。
- SQLite 采用事务、外键约束、任务／时间／状态及投递目标索引候选；候选和判定分页读取，避免每次刷新加载整次几十万候选。迁移需验证 WAL、磁盘满及清理中断情形。

## 8. DNS／通知与不确定结果

### 8.1 DNS 写入路径

1. 根据自动快照或本次手动显式选择建立目标清单，校验连接可用、目标身份仍一致、候选确为来源执行的合格 IP 且地址族匹配。历史连接引用不能复活失效凭据或授权任意新目标。
2. 同目标锁使用服务商＋账号稳定身份＋记录稳定 ID，而非仅连接名称；两个共享连接指向同一实际目标时仍必须串行。
3. 写前读取明确记录，确认类型、身份及需要保留的属性；只更新 IP。服务商是否支持最小字段更新及并发属性保护须核对，不能宣称远端具有未验证的 CAS 能力。
4. 明确拒绝保存脱敏失败，不清空、不换目标、不自动重试；成功记录最近写入来源及时间。
   - 目标发现／复核响应提供当前读取值与读取时间，并附本系统最近已确认写入的任务 ID、执行 ID 及写入时间；命名候选为 last_known_write，不作为原执行快照的一部分。未知字段为空并有明确说明，不以当前时刻或来源执行时间补齐，不覆盖其他任务的已知写入事实，也不宣称覆盖系统外全部变更。
5. 超时／断开记未确认，持有该目标序列直至本轮既定读取核对有结论；确认期望值则记录核对结果，仍不明确即保留未确认，不自动再次写入或回滚。
   - C-02 已确认：仍未确认时建立／更新实际目标的自动写入保护；后续自动投递在持有同目标锁后、发请求前检查最新保护，命中则不写入并保存未推送／跳过原因。此检查也覆盖更早入队的运行，不以当时快照没有保护为由绕过。
6. 核对相同 IP 不等于能证明谁写入；保留 API 收据与核对事实的区别，不把相同值伪造成可归因的服务商成功回执。
7. 人工从旧记录推送提示覆盖较新结果；人工重试是明确新尝试，可能重复写入的风险须保留。同目标按实际推送顺序生效，不新增“总是较新测量覆盖旧测量”的未确认政策。

### 8.1.1 未确认目标的自动保护与人工解除

- 保护键与同目标写锁使用同一规范身份，跨任务及连接别名共享；不是任务定时／自动推送开关，也不是第八种运行主状态。无保护目标、通知及全局 FIFO 不连带暂停。
- 自动命中保护只记录本次跳过及原未确认关联，不创建待解除后执行的写入积压。本轮其余收尾结束后照常落主状态并释放席位，优选成功不因目标保护变失败。
- 人工重试仍校验明确目标、合格 IP、地址族及连接权限，要求重复／迟到覆盖风险确认；与其他同目标写入串行，但不自动解除目标保护，即使该次响应明确成功。
- 只读查询／核对不写 DNS、不改变保护。明确解除是独立的已认证写动作，遵守 C-01 操作号、请求摘要及重复受理契约；只修改该目标资格并记录脱敏动作结果，不发送外部请求、不回放旧尝试、不补发已跳过投递，不改原未确认事实。
- 候选协议为 protection_revision 预期版本比较；解除与新的未确认事件竞争时，版本不一致拒绝解除并要求重新读取。保护重新形成时递增版本，不能让旧确认页或重复解除请求清掉新保护。
- 保护随数据卷持久化及一致性备份恢复，不因重启、连接改名、原运行／投递删除或操作日志过期自动消失；保护只保存必要非敏感追溯依据，不借此无限保存整个历史。启动遇到已发出但无确定收据的 DNS 请求，沿原未确认恢复规则建立或保留保护，不自动重放。
- 解除只表示共享管理者决定恢复自动资格，不能证明旧远端请求终止；本地锁、一次读取相同值或新的成功回执均不构成远端恰好一次保证。接口与界面必须保留这个风险边界，不能宣传暂停后绝不发生迟到覆盖。

### 8.2 通知与投递日志

- Telegram、企业微信分别形成 attempt，不因一渠道成功覆盖另一渠道失败；正常结束及取消例外有稳定事件标识，防页面刷新或重复 HTTP 请求再次发送同一已受理动作。
- 失败不自动重试，SDK 和传输层的隐式写重试也须关闭或核实；超时记未确认，不声称未送达，人工重发提示重复风险。
- 使用“持久化投递意图＋受控执行”保留证据，但不采用自动重放 outbox 的默认模式；重启后旧意图只供查看／核实，不驱动补发。
- 操作日志记动作受理及脱敏结果，投递明细保存逐次事实；二者不复制秘密，不把 HTTP 202 受理记为第三方已生效。
- 手动首次摘要发送与重发是不同动作意图：首次发送不要求原投递 ID，明确运行记录、渠道与可用连接引用后建立新投递；重发关联原尝试身份并仅处理本次显式选择的渠道。任务自动通知关闭或从未投递过，不能直接成为拒绝首次手动发送的条件；记录及连接可用性仍须服务端核验，不复活失效引用，不自动重绑连接、开启自动通知或重跑优选／DNS。
- 外部调用必须有有限请求及核对预算，以便进入失败或未确认结论。候选值为 DNS 写 10 秒、只读核对 5 秒、通知 10 秒；均为待验证技术参数，不是任务总超时或性能承诺，正文测量窗口仍按 PRD。

## 9. API 与前端协作契约候选

### 9.1 接口分组

路径仅作评审，不代表已有可调用实现。统一前缀候选为 `/api/v1`；页面路由独立于 API。

| 方法与资源 | 主要契约 |
| --- | --- |
| POST `/session`、DELETE `/session`、GET `/session` | 登录／退出当前会话／会话信息；会话通过受保护 Cookie 设置，响应正文不回传秘密。退出成功使当前会话立即失效并清理 Cookie，其他会话及后台任务不受影响；重复退出安全处理，不冒充退出全部 |
| GET／POST `/tasks`，GET／PATCH `/tasks/{taskId}` | 配置含每任务下载文件 URL（候选字段 download_url），默认来自 DefaultDownloadURL，可覆盖 HTTP／HTTPS；保存格式错误拒绝且不静默换址，快照固定当次非敏感值；返回版本，PATCH 带预期版本 |
| POST `/tasks/{taskId}/archive`、`/tasks/{taskId}/restore`、`/tasks/{taskId}/schedule-state` | 任务归档／恢复及计划开关；恢复响应返回任务身份、版本及关闭的定时状态，保留配置和历史，不执行运行或推送；区别于运行记录恢复 |
| POST `/tasks/{taskId}/runs`，GET `/tasks/{taskId}/runs` | 受理运行或查询该任务记录；触发返回 run_id／operation_id，不长连接等待整个优选 |
| GET `/tasks/{taskId}/runs/{runId}`、`/progress`、`/candidates`、`/snapshot` | 主结果、真实阶段进度、分页候选与脱敏快照，任务归属须一致 |
| POST `/runs/{runId}/cancel`，GET `/queue` | 取消收据与队列真实位置；停止受理和停止完成分开 |
| POST `/runs/{runId}/dns-deliveries`、`/runs/{runId}/notifications` | DNS 资源仅更新本次明确目标；摘要资源明确渠道／连接，首次摘要无需原投递 ID，重发关联原尝试；自动通知关闭不阻止首次手动摘要，发送摘要不触发测速／DNS；分别返回操作及逐目标／渠道尝试身份 |
| GET `/operations/{operationId}`、`/runs/{runId}/deliveries` | operationId 由网页提交前生成，首个响应丢失也已知；重新认证后仍按原号只读查原收据与关联对象，不隐式重试；未找到／过期不等于未执行，不暴露秘密 |
| DELETE `/runs/{runId}`，GET `/tasks/{taskId}/recycle-bin`，POST `/runs/{runId}/restore` | 二次确认已在 UI 完成，服务端仍检查活动保护；无直接永久删除 API |
| GET／POST `/connections`，GET／PATCH／DELETE `/connections/{id}`，只读 `/connections/{id}/dns-records` | 连接读取只给凭据设置状态且受引用保护；DNS 目标读取返回记录身份、当前 IP／读取时间、last_known_write，以及目标保护状态／原因／原未确认身份／形成时间／版本，未知字段如实说明 |
| GET `/dns-targets/{targetId}/auto-write-protection`，POST `/dns-targets/{targetId}/auto-write-protection/clear` | 查询及明确解除实际目标保护；解除带 operation_id、预期保护版本及风险确认，服务端核验规范身份及可用连接引用；成功不写 DNS、不补发、不改任务开关，冲突返回最新保护版本 |
| GET `/operation-logs`，GET／PATCH `/settings` | 日志只读条件查询；系统时区／历史设置变更独立校验，无日志逐条改删接口 |

### 9.2 幂等、冲突与错误

- C-01 已确认采用客户端提交前生成的稳定 operation_id 作为动作身份；写入携带该号，已有相同身份与请求摘要时返回原收据，不再次执行；同号不同动作或参数拒绝。若使用 Idempotency-Key 头，其值与 operation_id 同义，不再增加独立请求号映射；具体传输字段仍在接口细化时统一。
- GET 操作查询按该客户端已知身份只读找回原动作，仍须当前有效认证；身份不随重新登录或密码世代变化重命名，不恢复旧会话权限。网页仅保留最小非敏感操作标识，不保留秘密参数用于自动重交。
- 未找到、收据过期或历史清理后无法核验的旧操作身份不代表从未执行；查询不创建动作，不自动换号重发，旧号失效时不能重新作为新动作受理。人工明确的新尝试使用新的动作身份并保留原关联，未确认重复风险依既定投递规则提示。
- 这防止管理 API 重复受理，不是 DNS／通知的远端恰好一次保证。动作收据保留窗口与运行／日志清理的交互需细化；过期收据不能被解释为“从未执行”。
- 配置使用 revision／If-Match 候选协议，版本冲突返回最新版本信息，不自动覆盖其他共享使用者的编辑；秘密输入不得进入冲突比对响应。
- 候选错误码：AUTH_REQUIRED、AUTH_COOLDOWN、CONFIG_INVALID、REVISION_CONFLICT、TASK_BUSY、RESOURCE_IN_USE、RUN_NOT_ACTIVE、TARGET_CHANGED、EXTERNAL_RESULT_UNCONFIRMED、TARGET_PROTECTION_CHANGED；均需附中文说明和安全上下文。自动目标保护命中是本次跳过原因，不伪造成已发请求的失败或整个运行失败。
- HTTP 401 用于会话问题，400／422 校验，409 业务或版本冲突；记录不存在和任务归属不符使用一致的资源错误。读取 500 不返回空数组伪装成功。
- 成功受理用 202 及对象／操作 ID；参数错误定位到具体字段。响应需给服务端时刻、配置／进度版本及最后更新时间，以便前端展示陈旧信息而不是猜状态。

## 10. 认证、安全与部署信任边界

### 10.1 共享密码和秘密材料

- 密码环境变量优先；未配置则每次进程启动生成高熵新随机密码，密码世代更换使旧会话失效。KDF 存储验证材料，不将启动随机密码从数据卷恢复为旧登录权。
- 初始化获取方案候选：仅本机容器管理者可读的临时文件，位于非业务数据卷的受保护运行目录，目录 0700／文件 0600；不输出至普通启动日志、API 或页面。环境变量已配置时不另写明文副本。具体容器用户、读取流程及清理需技术验证。
- 会话采用高熵不透明 token＋服务端摘要，Cookie 建议 HttpOnly、SameSite=Lax，并在 HTTPS 部署下 Secure；最长 7 天，不以自动续期突破上限。退出结束当前会话，密码变化使全部旧会话失效。
- 同来源 15 分钟内 5 次失败后冷却 15 分钟；只信任配置内代理的转发头，不能任意使用 X-Forwarded-For；不锁全站。
- 连接凭据建议认证加密并有密钥版本；推荐外部只读秘密文件挂载主密钥，并纳入受保护的备份材料。主密钥首次初始化及是否提供受限卷内生成模式需 T-05 评审，不在此文放真实值。

### 10.2 主要威胁与约束

| 风险 | 设计缓解及验证边界 |
| --- | --- |
| 窃取会话／跨站发起写入 | HTTPS 同源、Cookie 与 CSRF／Origin 校验，敏感响应不缓存；所有 API 服务端认证，不依赖隐藏按钮 |
| 配置或错误泄密 | 白名单 DTO、结构化脱敏、不记完整认证请求或 URL 密钥，连接只显示已设置；审查日志及备份 |
| 用户来源／下载 URL 形成非预期代理或 SSRF | 仅认证管理者可配置，严格解析 URL／IP、固定服务商目标、控制重定向；探测本就是授权出站，不默认禁掉所有私网候选而悄悄缩减 PRD。部署网络隔离及特殊地址策略需安全联审 |
| 远端任务竞争／重发 | 稳定目标锁、持久动作身份、未确认不自动重试，重启旧意图不执行 |
| CSV／候选及任务名导致注入 | 使用结构化参数而非 shell 拼接，文本默认转义，数据库参数化；首期不新增 CSV 导出需求 |
| 多实例破坏全局串行 | 独占数据卷锁＋数据库槽与任务活动约束；不允许第二实例自行降级为另一个执行者 |
| ICMP 能力扩大容器权限 | 优先非特权能力探测，必要时最小 NET_RAW；不使用 privileged 或 NET_ADMIN 兜底，失败明确提示手动改 TCPING |

真实 Webhook、Token、服务连接或候选测速地址均未在本轮调用；威胁表是待验证设计，不是安全审计通过证明。

## 11. 容量、观测、迁移与故障恢复

### 11.1 可测量质量场景（候选，不是 SLA）

| 场景 | 要求／提案与验证方式 |
| --- | --- |
| 默认候选规模 | 单启用族最多 10000、两族各 10000；配置上限可达两族各 100000。分批生成／写入，分页查询；压力验证不能只跑默认小样本 |
| 延迟并发与下载 | 候选延迟探测采用有界 worker，初始建议 64 作为实验值；下载固定 1。验证吞吐、FD、内存及取消释放后再选默认，不新增前台并发配置或隐藏总任务超时 |
| 存储规模估算 | 假设每候选含索引前 0.5～1 KB：默认两族约 10～20 MB／次，最大两族约 100～200 MB／次；来源及判定、WAL、索引可继续放大，必须实测，不能视为容量承诺 |
| 进度读取 | 候选建议活动视图每 2 秒取小快照，列表每页 20、候选每页 50；测量大数据量下查询延迟及数据库写竞争，先不承诺响应 SLA |
| 任意一次长运行 | 可持续到完成、失败或人工停止；无整任务 TTL，不因压测慢自动截断预算。阶段请求／窗口的超时仅影响对应单元 |
| 停止与重启 | 新任务启动前旧探测／下载必须真正退出；模拟停止竞争、收尾重启及结果落库前崩溃，旧动作不得重放 |

可观测项：队列长度、当前运行及阶段、候选实际处理数／已知总量、阶段耗时、下载字节、取消等待、投递失败／未确认、DB 写耗时及磁盘错误。日志使用执行／操作／尝试 ID 关联，避免逐探测热日志或把 IP 当无限维指标标签；不输出秘密或虚构个人身份。

### 11.2 故障模式

| 故障 | 预期控制与未验证点 |
| --- | --- |
| 数据库不可写／磁盘满 | 不受理新动作，不在无法记录投递意图时发起外部写；已在途动作可能未确认，停止新的副作用并在恢复后保留该事实，不宣称外部未发生 |
| 来源或 ICMP 不可用 | 按基线部分来源继续／全部失败／协议不可用明确失败，不静默回退候选或测速方式 |
| 第三方超时 | 本轮有限请求与核对后形成失败或未确认，不自动重试；DNS 仍未确认则保存目标保护，后续自动命中跳过，仍正常收尾并释放全局席位；通知未确认不误建 DNS 保护 |
| 前端断开或会话过期 | 仅中断查看，不取消后台运行；重新认证后查原记录／操作，不自动重交 |
| 进程崩溃／容器重启 | 排队取消、运行中断，旧投递意图不重放；事务保证已提交事实可读，未确认窗口如实暴露 |
| 卷被两个实例使用 | 第二实例拒绝取得执行权；本地卷锁与文件系统语义须演练，不能承诺跨主机锁安全 |

### 11.3 从现有 CLI 迁移的建议路径

1. 保留 CLI 行为与用户工作区改动，以独立管理入口承接新业务；先分离引擎值对象及取消／进度契约，不把旧全局 flag 作为后台 API。
2. 新管理库按迁移版本初始化；首期不自动导入旧 CSV 为可信运行历史，不自动接管现有脚本或创建实际定时任务。
3. 以后若需历史导入，单独确认来源、缺失快照及测量口径，不以填默认值伪造旧事实。
4. 组件与依赖版本锁定后验证构建及许可兼容，继续遵守仓库现有 LICENSE；本轮不修改依赖、CI、CLI 或 Docker 文件。

### 11.4 数据与版本回退

- 卷级备份候选优先停机一致性备份，包含 SQLite／WAL 一致状态及受保护密钥材料；若在线备份，需使用数据库支持的一致性备份，不直接只复制主 DB 文件。
- 恢复到独占卷后按旧执行中断／取消规则初始化，不补跑、补发、恢复旧随机密码；日志事件时间不重置。恢复完成须核验配置、历史、引用及密钥可解密性。
- 升级前备份并记录 schema 版本；旧二进制不一定理解新 schema，不承诺只换镜像就可回退。不可逆迁移时回退到升级前完整卷，并说明期间数据可能丢失。
- RPO、RTO、支持 CPU 架构和资源限制尚无实测基线，列为后续部署验证输入，不凭文档给可用性承诺。DNS／消息的外部成功不随数据库回退撤销。

以下是技术选择，不是重新征询已确认的产品需求。

| 编号 | 推荐方案与理由 | 替代及复审条件 |
