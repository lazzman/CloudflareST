# 管理端滚动逻辑检查与修复

日期：2026-11-16。针对用户提供的新建任务长表单截图，复现并修正滚动容器、分组定位、返回位置和弹窗背景滚动。只改前端及测试，不改优选、DNS、通知、认证或数据库规则。

## 1. 已确认的问题

| 问题 | 修复前证据 | 修复后行为 |
| --- | --- | --- |
| 桌面长表单撑高整个应用，滚动属于外层页面 | 1440×900窗口中页面高3900px，滚轮后window偏移850px，应用外框向上移出视口 | 应用固定在可用视口；右侧内容区滚动850px，document偏移保持0，顶栏、侧栏和外框位置不变 |
| 表单分组跳转被顶栏遮挡 | DNS与通知分组顶部约0px，顶栏底部72px | 使用正确内容容器及滚动留白，分组标题在可视内容区内，不改变hash路由 |
| 弹窗打开时背景仍可滚动 | 内容位置1200px，弹窗外滚轮后变为1800px | 锁定真实滚动容器，弹窗内可滚动，背景不动；关闭后恢复原样式与位置 |
| 异步详情返回后丢失阅读位置 | 离开时1100px，返回加载后只剩2px | 路由按浏览器历史条目记录内容偏移；等待数据加载后恢复1100px，轮询不再重复恢复或跳顶 |
| 短桌面窗口侧栏底部不可达 | 420px高窗口中退出按钮位于545px | 导航列表可独立滚动，品牌与底部身份／退出区域保持可见 |

移动端保留正常整页滚动，不把桌面的内部容器方案强加给手机。320／390px下分组跳转、保存按钮可达、弹窗锁定与关闭后继续滚动均已验证。

## 2. 修复入口

- internal/management/web/src/style.css：桌面视口高度、容器min-height、内容滚动与侧栏导航独立滚动，分组留白、弹窗阻止滚动传递，移动端恢复文档滚动。
- internal/management/web/src/lib/scroll.ts：统一判断实际滚动容器；异步恢复期间用户主动滚动／点击／按键即取消恢复，避免随后抢回位置；嵌套弹窗使用计数锁并还原原有overflow。
- internal/management/web/src/router.ts：新路径回顶部，同路径筛选／分页保留位置；浏览器前进后退使用历史条目对应的位置，不按任务名称或路径猜测。位置只在当前页面内存中保留，不新增本地业务存储。
- App.vue、ModalDialog.vue：程序性路由焦点及关闭弹窗后的焦点恢复不再附带滚动；不取消原键盘焦点恢复。
- ResourceState.vue：明确初次／当前资源加载标记，滚动恢复等待内容可用；读取失败同样结束等待，不无限强行恢复。
- scripts/test-management-scroll.mjs、tests/scroll.test.ts：新增浏览器滚动专项及路由目标单元测试；CI已接入专项。

独立复核指出的桌面嵌套锁边界已单独复现并修复：首层锁定导航后，其overflow变为hidden，第二层仍必须计入该已锁导航；现在提前释放第一层不会解锁第二层仍使用的背景。
