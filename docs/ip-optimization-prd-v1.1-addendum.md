## 3. 业务规则增补

### 3.1 保护的触发及范围

1. 对一次已发起的 DNS 更新，若超时或断开且按既定规则读取核对后仍无法明确结果，将对应目标置为“待人工处理／自动写入暂停”，并关联未确认投递身份、原因及形成时间。
2. 暂停是目标级保护，不是任务定时开关、DNS 自动推送配置或新的运行主状态。目标身份取服务商、稳定账号身份及现存记录身份，而非任务名、连接显示名称或当次 IP。
3. 不同任务或多个连接别名指向同一实际记录时共用该保护；改名、换引用或新建别名不能静默绕过。同一账号其他记录、其他账号记录及通知渠道不受连带暂停。
4. 原始未确认投递保留未确认事实；增加保护不把它改为明确失败，也不伪造旧 IP 未改变。

### 3.2 对后续执行与全局席位的影响

1. 每次准备自动更新该实际目标时检查保护状态，包括已入队但尚未写入的运行；不只在保存任务或入队时检查。
2. 保护存在时，本轮该目标不发出 DNS 写请求，记录“未推送／跳过：目标待人工处理”，并可关联原未确认投递；不能为此排队等待人工处理，也不自动创建重试动作。
3. 继续处理本轮其他目标及通知，优选结果不变。各步骤已有本轮结论后，按原规则定稿主状态并释放席位，其他任务依 FIFO 继续。
4. 不自动关闭任务定时、任务 DNS 自动推送或通知开关；不能为“解除目标暂停”偷偷修改这些配置，也不将已跳过目标显示为推送成功。

### 3.3 人工重试与明确解除

1. 共享认证使用者可查看明确目标、原未确认操作、实际核对值／时刻及已知写入事实；查询仅用于判断，不自动发送写请求或解除保护。
2. 人工重试仍须选择合法合格 IP、匹配地址族与原已授权明确目标，并确认可能重复或被迟到旧请求覆盖的风险；保持同目标串行及受控操作收据。
3. 人工重试和解除暂停是两个明确动作。人工重试、一次成功回执、只读核对、页面刷新、经过一段时间、重启或恢复，均不自动代表用户已决定解除。
4. “解除自动写入暂停”显示具体目标、原未确认事实、仍可能迟到的风险及影响范围，确认后仅恢复该目标对后续自动写入的资格；不改写原投递事实、任务配置或其他目标。
5. 解除本身不更新 IP、不重新运行、不重发、也不补处理历史已跳过的自动推送。之后新发起的合法推送按当时有效开关与结果重新检查，不能把解除当作重试队列开闸。
6. 再次遇到未确认写入可重新形成保护；解除与新未确认事件发生竞争时不能清掉较新的保护原因。具体并发版本／锁协议由技术稿设计，不新增未经确认的自动解除政策。

### 3.4 持久化、删除及可观察性

- 目标保护是独立业务状态，应随数据卷持久化，重启不清除，备份恢复保留其已保存的状态；恢复不重放旧写入，不将恢复当作人工解除。
- 原投递、运行历史或操作日志到期清理，不因此解除尚待人工处理的实际目标。保护只保留追溯所需的非敏感标识、原因和时间，不能复制凭据或无限保留整份历史。
- 页面在目标选择／复核与投递详情展示保护及来源；自动跳过理由可查。共享认证后可发起明确解除，不新增个人角色或实名审批。
- 形成／重复命中保护、人工重试及解除的实际动作结果进入既定脱敏操作日志；操作日志仍固定保留 30 天，不因该状态新增独立或无限期的完整审计系统。

## 4. 目标状态与动作表

以下是目标自动写入资格，不是运行主状态，也不替代原投递结果。

| 当前目标状态 | 事件 | 结果及副作用 |
| --- | --- | --- |
| 无暂停保护 | 已发起写入且核对后仍未确认 | 保存未确认事实并建立该目标保护，不自动重试 |
| 自动写入暂停 | 后续自动推送 | 不发 DNS 请求，留跳过原因，其他目标及全局队列继续 |
| 自动写入暂停 | 明确人工重试 | 按原权限、目标、地址族及重复风险确认后处理；不自动解除保护 |
| 自动写入暂停 | 只读查询／核对 | 展示结果，不写 DNS，也不自动解除 |
| 自动写入暂停 | 人工明确解除 | 记录动作并解除该目标保护，不补发、不重跑、不改写历史事实 |
| 任意状态 | 重启／恢复／关联历史清理 | 不因该事件自动解除或重放；仍遵守原恢复与保留规则 |

## 5. 增量验收定义

以下为需求验收定义，不是测试已执行；AC-01～AC-104 原文保持不变。

- AC-105：已发起的 DNS 更新经既定读取核对仍未确认时，对对应实际目标建立自动写入暂停，保存原未确认身份、原因及时间；同实际记录的多个任务／连接别名均命中保护，不影响其他记录。
- AC-106：该目标有保护时，包括已入队尚未写入的运行在内，自动推送不发该目标写请求，记录未推送／跳过及原因；本轮其他目标和通知继续，正常完成优选且有结果时不因该跳过改为优选失败，全部收尾有结论后照常释放席位。
- AC-107：人工查看或重试须受认证及既定目标、地址族、单目标串行与重复风险约束；即使人工重试返回成功或读取到期望 IP，也不自动解除目标保护，不改写原未确认事实。
- AC-108：只有处理并明确执行该目标的解除动作才恢复后续自动写入资格；解除不改 IP、不重跑、不重试、不补发已跳过或历史操作，不更改任务开关或其他目标；再次发生未确认时可重新建立保护。
- AC-109：重启、同卷重建及备份恢复不自动清除已保存保护或重放写入；相关运行、投递或 30 天操作日志清理也不解除保护，非敏感保护依据仍可辨认，不保存秘密。
- AC-110：界面与查询区分原未确认投递、目标自动暂停及后续自动跳过；人工解除提示迟到覆盖风险，不能宣称远端旧请求已停止。解除若与新保护事件竞争，不得清除用户尚未处理的更新保护版本；形成保护及人工动作结果按原脱敏日志规则记录。
